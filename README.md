# IPTV 管理台

基于 Node.js 的自托管 IPTV 管理台，用于维护局域网 IPTV 的频道、RTP／UDP 组播线路、台标、电子节目单（EPG）和快速换台（FCC）配置。管理台生成 M3U 和 XMLTV。rtp2httpd 拉取 M3U、转发运营商组播并处理 FCC，播放器连接 rtp2httpd 收看。使用前需要准备可用的 IPTV 组播地址，以及能访问组播网络的 rtp2httpd 实例。

## 安装与启动

### 飞牛 fnOS

1. 确认 fnOS 版本至少为 **1.1.3100**，并在 NAS 上安装 **Node.js 22 或更高版本**。
2. 从 [GitHub Releases](https://github.com/shwhy1998/IPTV/releases/latest) 下载 `IPTV-<版本>-fnOS.fpk`，在飞牛应用中心手动安装并启动。
3. 使用 NAS 管理员账号从飞牛桌面打开 **IPTV 管理台**。管理入口由飞牛网关鉴权。
4. 在 rtp2httpd 中添加外部 M3U 来源 `http://<NAS 的局域网 IP>:8787/playlist.m3u`。如果应用使用了其他订阅端口，请替换示例中的 `8787`。

在飞牛版中，订阅端口只开放 M3U、XMLTV 和已上传的台标。管理页面和配置接口通过飞牛网关访问。

### 从源码运行

本机需安装 Node.js 22 或更高版本。在仓库根目录运行以下命令。

```sh
npm ci
npm start
```

打开 `http://localhost:8787/`。局域网中的 rtp2httpd 应使用运行管理台的主机 IP，例如 `http://192.168.1.10:8787/playlist.m3u`。独立模式监听全部 IPv4 网卡，管理页面和配置接口没有登录鉴权，请将端口限制在可信网络内。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `8787` | HTTP 监听端口 |
| `DATA_DIR` | 项目下的 `data/` | 频道配置和 EPG 缓存目录 |
| `PUBLIC_BASE_URL` | 根据 HTTP 请求的主机名和端口生成 | 指定 M3U 内 XMLTV 和上传台标链接的来源，例如 `https://iptv.example.com`。仅使用协议、主机名和端口 |

## 配置频道并接入播放器

1. 在管理台添加频道并填写组播线路。协议可选 RTP 或 UDP，地址填写 `239.1.2.3:1234`，需要指定源地址时使用 `10.0.0.1@239.1.2.3:1234`。同一频道有多条线路时，每条都要填写标签，例如「高清」和「超高清」。
2. 按需添加分组和台标。频道支持按名称和组播地址搜索，也可调整分组和频道顺序。台标可填写 HTTP(S) 图片链接，或上传 PNG、JPEG、WebP、GIF 图片。
3. 运营商提供 FCC 时，可在设置中填写默认 FCC 地址（`IPv4:端口`）和类型（电信或华为）。RTP 线路可以继承、覆盖或关闭 FCC。UDP 线路请关闭 FCC。
4. 在 rtp2httpd 中拉取或刷新外部 M3U，再把 rtp2httpd 提供的播放地址交给播放器。管理台的 M3U 保留组播地址、线路标签和 FCC 参数。

管理页面适配桌面和手机，支持日间、夜间及跟随系统主题。

### 订阅接口

| 路径 | 用途 |
| --- | --- |
| `/playlist.m3u` | rtp2httpd 的外部 M3U 来源，包含频道、线路、FCC、台标和节目单引用。加 `?download=1` 可下载文件 |
| `/epg.xml` | 合并已关联频道的 XMLTV 节目单，支持 gzip 和 ETag |
| `/logos/<频道 ID>` | 提供从管理台上传的台标。使用外部图片链接的频道直接在 M3U 中引用原地址 |

M3U 中的链接默认使用拉取请求的主机名和端口。请用 rtp2httpd 和播放器均可访问的地址订阅。独立部署在反向代理后时，可通过 `PUBLIC_BASE_URL` 指定对客户端可达的站点地址。

## 电子节目单

- 默认预置上海电信 EPG 源。可在「设置」中添加多个 HTTP(S) XMLTV 源，支持普通 XML 和 gzip 压缩文件。
- 保存节目单地址后，手动刷新单个源或全部源。在频道编辑页按名称或 ID 搜索，选中节目单频道并保存关联。
- 默认每天北京时间 **00:40、06:40、13:40、18:40** 刷新，可在设置中修改。应用启动时会尝试刷新缺少有效缓存的源。同一地址刷新失败时会继续使用最近一次成功缓存。更换源地址后需重新拉取。
- 合并节目单只包含已关联且有缓存的频道。不同来源使用相同的原始频道 ID 时，管理台会在合并节目单和 M3U 中生成相互匹配的 ID。仅配置一个 EPG 源且尚无缓存时，M3U 会临时引用该源的原始地址。

## 数据与排查

- `settings.json` 保存频道、线路、EPG 关联、FCC 设置和已上传的台标。`epg/` 保存各源的 XMLTV 缓存。备份时复制整个数据目录，恢复时先停止服务再把备份放回原数据目录。
- 独立运行时，数据位于 `DATA_DIR` 指定的位置或项目的 `data/`。飞牛版优先使用应用数据共享目录 `iptv-manager/data`，不可用时使用应用变量目录下的 `data/`。升级会沿用已有配置，并在共享目录尚无配置时尝试迁移旧数据。
- 飞牛应用启动失败时，检查 Node.js 版本、订阅端口是否被占用，并查看应用变量目录下的 `app.log`。
- 能订阅 M3U 但无法播放时，先确认 rtp2httpd 已刷新外部 M3U，再检查 rtp2httpd 主机是否能接收对应组播。订阅成功只验证列表可获取。
- 节目单为空时，先检查源的刷新状态，再确认对应频道已保存 EPG 关联。播放器还需要能访问 M3U 中引用的节目单地址。

## 代码与发布

| 路径 | 职责 |
| --- | --- |
| [`server.js`](./server.js) | Node.js HTTP 服务、配置校验和持久化、M3U 与台标输出 |
| [`epg.js`](./epg.js) | XMLTV 拉取、定时刷新、缓存和多源合并 |
| [`public/`](./public/) | 原生 HTML、CSS 和 JavaScript 管理页面 |
| [`fnos/`](./fnos/) | 飞牛网关配置、应用生命周期脚本和 FPK 构建脚本 |
| [`logo/`](./logo/) | 单独维护的公开台标资源与来源说明，可按需用作频道台标 |

在 Linux 上准备 Node.js 22+ 和 `fnpack` 后，可从仓库根目录构建 FPK。若 `fnpack` 不在 PATH 中，通过 `FNPACK` 指定其绝对路径。

```sh
npm ci --omit=dev --no-bin-links
node fnos/build.mjs 1.0.0
```

产物为 `dist/IPTV-1.0.0-fnOS.fpk`。应用代码、依赖或打包相关配置推送到 `main` 后，[GitHub Actions](./.github/workflows/fnos-release.yml) 会进行语法检查、构建并检查 FPK，再发布安装包、SHA-256 校验文件和版本说明。仅更新 README 或 `logo/` 不会触发自动发布。
